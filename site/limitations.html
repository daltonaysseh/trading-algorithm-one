Data quality & limitations

Every real problem found while building this pipeline, logged as it was found. This is a research project, not a pitch — if something here would change how you read the Results page once it exists, that's the point of listing it.

high severity

MAJOR PIVOT: backtest research cancelled in favor of a live analyzer

documented  ·  found 2026-08-11  ·  affects: Whole project direction

This project began as a backtest (does earnings-call sentiment predict forward stock returns?) with a 10-ticker validated batch, 183 ingested transcripts, and a scale-up scoring effort (18/183 done when the pivot landed). That work is cancelled, not paused -- the new goal is a live tool that analyzes any ticker's most recent call on demand, framed as a communication-quality read for analyst research, not a return- prediction system. The 10 already-scored transcripts were kept as rubric reference/proof-of-concept examples (see the Examples page); Phase 3 (price data) and Phase 4 (backtest) were never started and are now off the roadmap. The rubric itself (config/rubric.md v2) carried forward unchanged into the live tool.

Rubric hasn't been independently audited at scale

documented  ·  found 2026-08-11  ·  affects: All scoring, all tickers

The 5-dimension rubric (guidance, hedging, qa_directness, consistency, headwinds) is adapted from an earlier, separate project (Equity Research) that had no written scoring criteria at all -- only column names. This project supplied written criteria (config/rubric.md) and sharpened two dimensions after measuring real compression (see the qa_directness/consistency entry below), but there's been no independent audit of live-tool scores against a second scorer's judgment, no inter-rater check, and no systematic spot-check across a large sample of live analyses. Treat every score as a structured first read, not an audited measurement.

Prepared-remarks/Q&A split had a real bug affecting ~46% of transcripts

documented  ·  found 2026-08-11  ·  affects: Was 84/183 transcripts; now 4/183 (see next entry)

Caught before any scoring happened, by hand-reading a transcript (CSGS Q2 2025) before scoring it, per an explicit instruction to pair scores with real excerpts. The original phrase-matching split logic mismatched a Python truthiness check (`if qa_start_idx else ...` silently mishandled a legitimate index of 0) and also false-matched an operator's or executive's own PREVIEW of the Q&A session (e.g. a CFO's closing line "I'll turn it over to the operator to facilitate the Q&A") as if that were the Q&A starting. This affected 84 of 183 (46%) stockanalysis.com-sourced transcripts before being fixed. Replaced with a structural method: each source turn carries the speaker's employer; the first turn whose employer differs from the reporting company's own (i.e. an outside analyst) reliably marks the real Q&A start. Final state: 179/183 (97.8%) verified real splits.

medium severity

Live-analyzer scoring consistency with the reference examples is unverified

monitoring  ·  found 2026-08-11  ·  affects: All live analyses

The 10 calibration examples and all future live analyses are scored by the same process (Claude reading the transcript against rubric.md inside a session) -- there's no separate automated scorer to check against, and no formal re-test of whether live analyses land on the same scale as the reference examples did. Worth a periodic spot check: re-analyze one of the 10 reference tickers' same historical quarter and confirm the score lands close to its recorded calibration score.

Two tickers (MLI, NHC) had no transcripts on either source -- a live-tool failure mode too

documented  ·  found 2026-08-11  ·  affects: Any live analysis of a thin-coverage ticker

Mueller Industries (MLI) and National HealthCare Corp (NHC) were the original picks for the Industrials and Health Care slots in the old validation batch. Neither has a transcript on stockanalysis.com or fool.com -- confirmed, not just a coverage gap; replaced in the batch at the time. This same failure mode applies to the live analyzer now: any thinly-covered ticker a user asks about can hit it, which is why fetch_latest.py returns an explicit "not found" status rather than failing silently or fabricating a report.

One transcript has upstream-mislabeled content (USPH "Q3 2025")

excluded  ·  found 2026-08-11  ·  affects: USPH "Q3 2025" row only (1 of 183) -- flagged in DB via data_quality_flag

The DB row labeled USPH Q3 2025 (call_date 2025-11-06) contains the text of the Q2 2025 call instead -- explicit "Second Quarter 2025 Earnings Call" self-statement, April/May/June visit data discussed. Verified this isn't a local duplicate (distinct from the correctly- labeled USPH Q2 2025 row). Most likely an upstream stockanalysis.com/ Quartr content-serving error. Found via a systematic self-consistency check (each transcript's own stated quarter vs its DB label) run across all 183 rows after this specific failure mode was caught by hand-reading the transcript before scoring. Excluded from scoring; the reference example shown for USPH on this site is for the correctly-labeled Q2 2025 transcript instead. Worth remembering for the live tool too -- always worth a sanity check that the transcript's own self-stated quarter matches what was asked for.

qa_directness/consistency anchors were too compressed to discriminate (fixed, v2)

documented  ·  found 2026-08-11  ·  affects: qa_directness and consistency dimensions, all 183 transcripts

Before scaling past the 10-transcript calibration batch, measured whether qa_directness/consistency showed real discrimination or just clustered around one outlier. They clustered: excluding PBF (the one unambiguous case), consistency had a 10-point range and stdev 4.4 across the other 9 transcripts (75/80/85 only), qa_directness stdev 7.0 -- while guidance/hedging spread across their full range (stdev 12-15) with no single-outlier dependency. The rubric was functioning as a binary "blatant stonewalling" detector on these two dimensions, not a continuous scale -- a real problem for comparing calls to each other meaningfully, which needs separation across the whole distribution, not just at one extreme. Fixed by expanding both dimensions from a 3-point (20/50/80) to a 6-point anchor (see config/rubric.md v2) and re-scoring all 10 calibration transcripts under it. Result: qa_directness stdev 14.0 -> 18.4, consistency stdev 12.9 -> 19.0, and PBF's composite correctly dropped further from the pack (42 -> 36) instead of being pulled toward it by a compressed scale. All 183 transcripts (the original 10 re-scored, the remaining 173 scored fresh) use v2.

4 UTL transcripts have no Q&A content in the source data at all

documented  ·  found 2026-08-11  ·  affects: Any thin-coverage ticker with no analyst Q&A in a given quarter

UTL Q1 2023, Q2 2023, Q3 2022, and Q1 2025 end immediately after the operator's Q&A instructions, with zero analyst turns anywhere in the source data -- confirmed by hand, not a detection failure. Most likely genuine (very light analyst coverage for a small utility) rather than a transcription gap. The live analyzer handles this the same way: scores on full text only when no Q&A turns are found, rather than forcing a split that doesn't exist.

One transcript has a source diarization defect (SHEN Q3 2025)

monitoring  ·  found 2026-08-11  ·  affects: SHEN Q3 2025 only -- one exchange misclassified

The source data merged the operator's introduction of the first analyst (Frank Loudon) and his entire question into the Operator's own turn object, with no distinct speaker/company tag. The structural Q&A-split method correctly found the *second* analyst but missed the first, so that one exchange landed in the "prepared_remarks" bucket for this transcript. Not auto-detectable at scale from the data available; noted as a residual limitation category rather than individually patched.

An earlier iteration added a quant-fundamentals snapshot (composite + Quality/Growth/Valuation/Financial Health, via a reused stock_scorer.py from the sibling Equity Research project) to each ticker's report page. Older fool.com transcripts have a speaker-attribution parsing defect

monitoring  ·  found 2026-08-11  ·  affects: fool.com-sourced transcripts on the older page template (at least SCVL_Q1_2021; extent across the other 22 fool.com rows not yet checked)

SCVL_Q1_2021 (and likely other fool.com-sourced transcripts using the same older ~2021-era page template) has every line tagged [Operator] in the raw JSON, regardless of actual speaker -- fool_fetch.py's speaker-detection logic (looks for a standalone `<p><strong>Name</strong></p>` tag) doesn't match this older template's HTML structure, so `current_speaker` never updates from its initial "Operator" default. Content and paragraph-level text are still fully intact and readable (verified by hand-reading SCVL_Q1_2021 before scoring) -- this is cosmetic to the `speaker` field only, doesn't block scoring, but any downstream code that trusts `speaker` for these rows will be wrong. Not yet checked systematically across all 23 fool.com-sourced rows; flagging as "monitoring" until that sweep happens.

Each live analysis is a single read, not a repeated-measures average

documented  ·  found 2026-08-11  ·  affects: All live analyses

One transcript gets scored once, by one read. There's no ensembling, no re-scoring for stability, and no confidence interval on any score -- a genuinely borderline call (e.g. a guidance score right between two anchor points) could land a few points differently on a re-read. Treat single-point scores as approximate, especially for values close to a rubric anchor boundary.
